## Podsumowanie dla issue Nordica

1. **Run 1:** Reprodukowalny RCP cliff — 75× OK → fail @ 76, `radio tx timeout` → `RecoverFromRcpFailure`.
2. **Run 2:** 1600 B fragmentacja OK; **1700 B** — TX fragmentów jest, brak echo (router).
3. **Run 3:** Do SED duże pingi idą przez air; TM ERROR to parser (7 RX / 5 TX).
4. **Run 4:** Krótki iperf OK, potem ten sam RCP crash; fragmentacja widoczna w PCAP.

**Znany bug RCP:** DUT traci TX pod sustained large packets (1000 B+) → `radio tx timeout` → `RecoverFromRcpFailure()` @ `radio_spinel.cpp:2068`.

**Known issues frameworka (nie bug RCP):**

- `_probe_connectivity_on_failure()` pada na martwym netns → cliff debug kończy się ERROR zamiast FAIL + pełne `session_data`.
- tearDown: `vendor:fault:info` na bare-metal → `InvalidCommand` (szum).
- Parser pinga: `Received more packets than transmitted` na SED z duplikatami echo.

**Przed kolejnymi testami:** power-cycle obu płytek (RCP martwy po Run 1/4).
